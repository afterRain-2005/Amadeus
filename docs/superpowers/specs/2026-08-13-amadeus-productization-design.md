# Amadeus 产品化设计文档

> 日期：2026-08-13
> 状态：设计已与用户逐段确认，待用户最终审阅
> 定位：自用项目，追求**商业级产品质感**（美观 / 完成度 / 功能性），不售卖、不变现

---

## 1. 背景与问题诊断

当前 `amadeus-py` 是一个单机 Live2D 桌宠 + 聊天应用，技术栈 PySide6 + pywebview + Live2D，后端依赖本地 Hermes gateway 或直连 LLM。代码审查（[lessons.md](../../../lessons.md)、[config.py](../../../config.py)、[desktop_pet.py](../../../desktop_pet.py)、[session_manager.py](../../../core/session_manager.py)）发现四类"玩具感"：

1. **视觉与交互粗糙**：缺加载/空/错误/过渡状态，配色字体间距不统一
2. **功能不完整/不鲁棒**：记忆为纯正则抽取且只活在单会话内（[session_manager.py:69-77](../../../core/session_manager.py#L69-L77)），换会话即失忆
3. **工程不扎实**：硬编码假账号密码（[config.py](../../../config.py) `Amadeus/0728`）、文件轮询 IPC（`pet_command.json`，[lessons.md 教训2](../../../lessons.md)）、大量死代码、手动 start.bat、无打包规范
4. **产品定位太浅**：被动响应，无主动关心、无上下文感知、无长期记忆钩子

## 2. 产品主线（用户确认）

**一个深度融入日常电脑使用与工作的 AI 伴侣——她记得你、会主动关心、能帮你干活，保留命运石之门红莉栖角色沉浸感。** 综合伴侣（陪伴 + 助手 + 沉浸），自用。

### 关键决策（用户逐项确认）

| 决策点 | 选择 | 含义 |
|---|---|---|
| IP 取舍 | 保留石头门角色，非营利同人自用 | 不售卖，红莉栖角色可保留 |
| "商业级"含义 | 美观 + 完成度 + 功能性，非变现 | 聚焦产品质感 |
| 产品主线 | 综合伴侣（全都要） | 陪伴 + 助手 + 沉浸 |
| 集成深度 | 能力全开但用户可控 | 感知能力逐项开关，默认多数关 |
| 路径 | B 骨架 + A 节奏 | 三层目标架构 + 分阶段可验证实现 |
| Hermes | 两者都保留但默认直连 | 直连 LLM 为默认，Hermes 可选高级 |
| 记忆隔离 | 按角色隔离 | 红莉栖有自己的记忆（单角色下自然满足） |
| Embedding | 本地嵌入模型 | sentence-transformers，离线、隐私，接受 ~500MB 依赖 |
| 角色 | **只要红莉栖** | 移除多角色机制，移除登录 |
| 登录 | **不要登录** | 启动直接进桌宠 |
| 自动更新 | 只版本提示 | 启动检查版本号，不自动下载安装 |

## 3. 目标架构：常驻 Amadeus 服务 + Live2D 作为"脸"

把当前"main → desktop_pet 子进程 → renderer 子进程 + 文件轮询 IPC"重构为**单常驻服务进程**，内部三层清晰边界：

```
┌──────────────────────────── AmadeusService（常驻主进程）────────────────────────────┐
│  调度器 Scheduler ── 主动触发（久坐/深夜/工作节奏/定时）→ 生成主动消息              │
│                                                                                        │
│  感知层 Perception（全部可开关，落实"能力全开但用户可控"）                          │
│    ├ ActiveWindowSensor  当前在哪个窗口/应用（默认开，低风险）                      │
│    ├ ActivityTracker     工作节奏/久坐/空闲（默认开，不记录按键内容）              │
│    ├ ClipboardSensor     剪贴板（默认关）                                           │
│    ├ ScreenSensor        屏幕感知送视觉 LLM（默认关，最重最敏感）                  │
│    └ CalendarSensor      日程（默认关）                                             │
│                                                                                        │
│  记忆层 Memory（替代纯正则抽取）                                                      │
│    ├ SQLite：结构化 facts / episodes（事实+事件）                                   │
│    └ 向量库：本地 sentence-transformers embed 对话片段，语义召回跨会话跨天          │
│                                                                                        │
│  对话层 Conversation                                                                    │
│    └ agent_client：默认直连 OpenAI 兼容 API；Hermes 作可选高级模式                 │
│      注入 = 人设 + 感知上下文 + 召回记忆 + 历史                                      │
└────────────────────────────────────────────────────────────────────────────────────┘
          ▲ 进程内 Qt 信号（取代 pet_command.json 轮询）
          │
┌─────────┴─────────── PetUI（Live2D 桌宠，"脸"）──────────────────────┐
│  PySide6 透明覆盖层 + Live2D 渲染 + 气泡 + 输入框 + 状态系统          │
└──────────────────────────────────────────────────────────────────────┘
```

### 架构原则
- **隔离与清晰**：感知 / 记忆 / 对话三层各有单一职责、定义良好的接口，可独立理解与测试
- **进程内通信**：PetUI 作为 AmadeusService 的进程内组件，Qt 信号直传，消灭文件轮询
- **默认鲁棒**：默认走直连 LLM，Hermes 失败/未启用不影响主流程
- **隐私可控**：每个传感器在设置中独立开关，用户可见感知到的数据

## 4. 分阶段路线图（每阶段独立可验证、可 git 存档）

| 阶段 | 主题 | 关键交付 | 消除的玩具感 |
|---|---|---|---|
| **P0 清债** | 工程治理 | 删死代码、移除多角色(只留红莉栖)、去登录、文件 IPC→进程内信号、统一设置 UI、打包规范化、版本提示 | 工程不扎实 |
| **P1 记忆** | 她记得你 | SQLite+本地向量记忆替代正则，跨会话跨天，LLM 抽取，记忆注入对话，设置可见可控 | 功能不完整、定位浅 |
| **P2 感知** | 上下文感知 | 各传感器 + 设置逐项开关，感知上下文注入对话 | 定位浅、功能不完整 |
| **P3 主动** | 主动陪伴 | 调度器 + 久坐/深夜/节奏触发主动关心提醒 | 定位浅（核心钩子） |
| **P4 视觉** | 质感打磨 | UI 状态系统、设计系统统一、微交互、启动仪式 | 视觉粗糙 |

> 视觉为贯穿关切：P0 起即补廉价的 loading/empty/error 状态，P4 做深打磨。
> 记忆 P1 排在前，因"她记得你"是综合伴侣的灵魂，定调最早、收益最大。

## 5. 记忆层详细设计（P1）

### 三层记忆结构

| 子层 | 存储 | 内容 | 写入时机 |
|---|---|---|---|
| **事实记忆** | SQLite `facts` 表 | "用户名=小明""用户在赶毕业论文""不喜欢香菜" | LLM 抽取（非正则），每轮对话后异步提取 |
| **事件记忆** | SQLite `episodes` 表 | "8-13 23:00 用户熬夜赶论文，红莉栖劝他休息" | LLM 抽取关键事件 |
| **语义记忆** | 本地向量库（sentence-transformers） | 过往对话片段的向量表示 | 每轮对话后 embed 存入 |

### 召回与注入伪代码

```python
def build_context(user_msg: str, character_id: str) -> str:
    active = sql("SELECT * FROM facts WHERE active=1 AND char=?", character_id)  # 用户名等常驻
    facts = sql("SELECT * FROM facts WHERE char=? AND relevance_high", character_id)
    episodes = vector_search(user_msg, k=5)        # 语义召回过往片段
    return f"【用户记忆】常驻:{active}\n相关:{facts + episodes}"
```

### 用户可见可控
设置页"记忆"tab：查看 / 编辑 / 删除记忆条目（商业级产品标配，也方便纠错与隐私）。

### 隔离
按角色隔离（用户确认）。单角色（红莉栖）下自然满足，但 schema 保留 `char` 字段以备未来扩展。

### 依赖
新增 `sentence-transformers`（含模型，约 500MB）、`sqlite-vec` 或 numpy 余弦（轻量本地向量检索）。Embedding 模型首次启动加载，之后常驻内存。

## 6. 感知层详细设计（P2）

| 传感器 | 实现 | 默认 | 隐私 |
|---|---|---|---|
| ActiveWindow | win32 `GetForegroundWindow` + `GetWindowText`，轮询 2s | 开 | 低（仅窗口标题） |
| ActivityTracker | `GetLastInputInfo` 算空闲/工作节奏 | 开 | 低（不记录按键内容） |
| Clipboard | 剪贴板变化监听 | 关 | 中 |
| Screen | 按需截屏送视觉 LLM | 关 | 高（最重最敏感） |
| Calendar | 读 Windows 日历 / .ics | 关 | 中 |

### 上下文快照注入
感知层产出紧凑快照（如"用户正在 VS Code 编辑 amadeus-py，已连续工作 2h"），对话时注入 system prompt；同时喂给 P3 调度器触发主动关心。

### 隐私边界
- 每个传感器在设置中独立开关
- Screen / Clipboard 默认关
- 用户可在设置查看"当前感知到的上下文"
- 所有感知数据本地存储，不出本机

## 8. 视觉打磨详细（P4，P0 起补廉价状态）

- **UI 状态系统**：每个交互具备 loading / empty / error / success 状态（当前全缺，最重玩具感来源）
- **设计系统统一**：萌系粉 + iOS 蓝 `#007AFF` / iOS 红 `#ff3b30` / iOS 灰 `#8e8e93`，统一圆角/阴影/字体/间距，组件复用（沿用用户既有 UI 偏好）
- **微交互**：hover、过渡动画、气泡进出、Live2D 情绪平滑过渡
- **状态文案角色化**：错误/空态用红莉栖语气而非 "Error"（如"…信号不太好，等一下"）
- **启动仪式感**：加载动画替代闪现，强化"她在醒来"的沉浸感

## 9. 错误处理与鲁棒性

- **后端降级**：Hermes 失败自动回退直连 LLM；直连失败向用户显示角色化错误态并保留输入
- **记忆降级**：向量检索失败时仅用 SQL 事实记忆；SQLite 损坏时备份后重建
- **感知降级**：任一传感器异常不影响其他传感器与对话主流程
- **崩溃恢复**：服务进程异常退出后，下次启动恢复上次会话与记忆

## 10. 测试策略

- **单元测试**：记忆层（抽取/召回/注入）、感知层（各传感器 mock）、对话注入拼装
- **集成测试**：三层联调（感知→记忆→对话注入）
- **手动验收**：每阶段交付前用户验证 → git 存档（遵循用户规则）

## 11. 不做（YAGNI）

- ❌ 平台化 / 多 IP 角色引擎（自用，过度工程）
- ❌ 自动更新下载安装（只要版本提示）
- ❌ 多角色（只要红莉栖）
- ❌ 登录系统（自用无需）
- ❌ 商业变现 / 计费 / 账号体系

## 12. 待定 / 风险

- **资产清理**：移除真帆/真由理后，其 Live2D 模型文件夹（`maho-l2d` / `MAY-l2d`）与语音样本是否删除——建议保留在磁盘但不在 config 暴露，避免不可逆删除；最终由实现阶段决定
- **本地嵌入模型选型**：sentence-transformers 具体模型（如 `paraphrase-multilingual-MiniLM-L12-v2` 支持中日英）在 P1 实现时选定
- **IPC 重构风险**：进程内化是 P0 最大改动，需充分手动验证情绪/语音同步不回归
