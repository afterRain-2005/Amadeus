## 一、项目定位

Amadeus-py 是一个基于 PySide6 的桌面 AI 伴侣应用（以《命运石之门》红莉栖为角色原型），核心能力包括：

1. **透明桌宠 UI** — Live2D 模型 + 透明无边框窗口浮于桌面
2. **多后端 AI 对话** — 本地直连 / DeepSeek / Harness / Codex / Hermes 五种路由模式
3. **半双工语音通话** — VAD → ASR → LLM → TTS 全管线，支持屏幕共享给 AI
4. **Companion 主动陪伴** — 传感器驱动的伪春菜式主动问候系统
5. **桌面工具执行** — 文件操作、PowerShell、GUI 自动化、网页抓取

## 四、技术栈

| 层次 | 技术 |
|------|------|
| UI 框架 | PySide6 (Qt for Python) |
| Live2D 渲染 | cubism4.min.js + pixi.min.js (webview) |
| AI 后端 | OpenAI 兼容 API / DeepSeek / Harness SDK / Codex CLI |
| 语音识别 | 小米 mimo ASR (httpx) |
| 语音合成 | GPT-SoVITS / 阿里云 TTS |
| 屏幕捕获 | mss |
| 数据存储 | JSON (config.json) + SQLite (companion) |
| 进程通信 | multiprocessing.Pipe (duplex) |
| 打包 | PyInstaller (Amadeus.spec) |
| 测试 | pytest |
| 第三方框架 | deepseek-harness-master (TypeScript，vendored) |

## 五、已知技术债（"屎山"特征）

| 编号 | 问题 | 影响 | 优先级 |
|------|------|------|--------|
| TD-01 | `desktop_pet.py` 单文件 ~2300 行，UI/逻辑/进程管理/HTML渲染/GPT-SoVITS 启动全混在一起 | 维护困难、合并冲突频发 | P0 |
| TD-02 | `desktop_pet.py` 内嵌大量 HTML 字符串（_build_kurisu_html 等），前后端耦合 | 前端改动需改 Python | P1 |
| TD-03 | `backend_router.py` 的 route_and_send 函数 ~150 行，5 种路由分支硬编码 | 新增后端需改大函数 | P1 |
| TD-04 | config.py 承担角色定义 + 所有默认配置 + 资源路径，职责过重 | 配置变更影响面大 | P2 |
| TD-05 | companion/storage.py 与 core/storage.py 同名但功能不同，易混淆 | 命名歧义 | P2 |
| TD-06 | 测试覆盖不均：companion 全覆盖，voice_call/desktop_tools 仅冒烟测试 | 回归风险 | P2 |

## 六、外部依赖边界

| 依赖 | 说明 | 是否可改 |
|------|------|----------|
| `deepseek-harness-master/` | TypeScript vendored 项目，提供 Harness SDK + Cordis 框架 | **不可改**，视为外部库 |
| `resources/live2d/` | Live2D 模型资源文件 | 只增不改 |
| `.venv/` / `gpt_sovits_venv/` | Python 虚拟环境 | 不纳入版本管理 |
| `data/harness/cordis.full.yml` | Harness 运行时配置 | 可改但需同步 harness_bridge.py |
